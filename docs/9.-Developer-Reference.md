# 9. Developer Reference — Helpers & Extensions

> 👤 For: **Developer** — Reference for Razor helpers, C# extension methods, tag helpers and utility classes used in views.

uTPro ships a set of Razor/C# helpers used throughout the views. This page is a quick reference for developers building components and templates. Add `@using uTPro.Extension;` (and `@using uTPro.Extension.CurrentSite;`) where needed — most are already imported via `_ViewImports.cshtml`.

> The **Script Queue** helpers (`QueueScript` / `QueueStandaloneScript`) have their own page — see [5. Script Queue](/5-Script-Queue/).

## 9.1 Current site & item context

`ICurrentSiteExtension` (injected as `CurrentSite` in views) gives per-request site context:

| Member | Returns / does |
|--------|----------------|
| `CurrentSite.GetItem()` | The current site's key nodes (see below) |
| `CurrentCulture` | The active `CultureInfo` |
| `DefaultCulture` | The site's default culture |
| `GetCultures()` | All published cultures (used for the language switcher) |
| `GetDomains(bool isGetAll)` | Configured domains for the site |
| `GetUrlWithCulture(content, culture, mode)` | URL of a node in a specific culture |
| `GetDictionaryValue(key, valueDefault = "", showKey = false)` | Dictionary translation lookup |
| `SetCurrentCulture(culture)` | Override the request culture |

`CurrentSite.GetItem()` returns an `ICurrentItemExtension` exposing the site's structural nodes:

| Member | Node |
|--------|------|
| `Root` | `GlobalRoot` (also `Root.Name` — used as the per-site CSS/JS folder name) |
| `FolderSite` | `GlobalFolderSites` |
| `FolderSettings` | `GlobalFolderSettings` (favicon, responsive-image & SMTP settings live here) |
| `PageHome` | The site's Home page |
| `Current` | The current page |
| `PageErrors` | The error page node |

```razor
@inject ICurrentSiteExtension CurrentSite
<link rel="stylesheet" href="~/css/@CurrentSite.GetItem().Root.Name/Components/MyComponent.css" />
<span>@CurrentSite.GetDictionaryValue("uTPro.Form.ContactUs.Message")</span>
```

## 9.2 Content inheritance

`ContentExtensions` resolves values inherited down the content tree (self → ancestors), with per-request caching:

```razor
@* First ancestor (or self) that has "topComponent" *@
var top = Model.ValueInherited<BlockGridModel>("topComponent");

@* The node that holds the value, for a set of aliases (first match wins) *@
var (alias, node) = Model.Inherited("bannerImage", "defaultImage");
```

Used by the page templates for `topComponent` / `bottomComponent` so a value set on `Home` cascades to child pages.

## 9.3 Media & responsive images

**`ResponsiveImg(...)`** (`ResponsiveImageExtension`) renders a responsive `<img>` (WebP + `srcset`), driven by [Responsive Image Settings](/8-Global-Settings/#83-responsive-image-settings):

```razor
@image.ResponsiveImg(
    alt: "Hero banner",
    cssClass: "hero-img",
    sizes: "100vw",
    priority: true)      @* LCP/above-the-fold: eager + fetchpriority=high *@
```

Key parameters: `alt` (falls back to the media's `altText`), `cssClass`, `sizes` (default `100vw`), `lazy` (default `true`), `priority` (LCP images), `includeDimensions` (default `true`, prevents layout shift), `quality` (default `80`). Non-image media or the toggle being off emits the original URL untouched.

**`ValueToMedia*`** (`ValueToMediaUrlExtension`) returns a media **URL string** for a property alias, resized to a breakpoint and converted to WebP (images only; other media returns the absolute URL):

| Method | Target width |
|--------|--------------|
| `value.ValueToMediaDesktop("alias")` | 2048 |
| `value.ValueToMediaTablet("alias")` | 1500 |
| `value.ValueToMediaMobile("alias")` | 800 |
| `value.ValueToMedia("alias", format: "WebP")` | original (format-converted) |

```razor
<img src="@Model.ValueToMediaDesktop("image")" alt="@Model.Value("title")" />
```

## 9.4 HTML & string helpers

| Helper | Signature | Purpose |
|--------|-----------|---------|
| `ToHtml()` | `string?.ToHtml()` / `IHtmlEncodedString?.ToHtml()` | Renders CMS HTML with a **best-effort** neutraliser (strips `script`/`style`/`iframe`/`object`/`embed`/`base`/`form`, inline `on*` handlers and `javascript:`/`vbscript:`/`data:` URIs). **Not** a full sanitizer — don't rely on it for untrusted input. |
| `ToInline()` | `string?.ToInline()` / `IHtmlEncodedString?.ToInline()` | Collapses newlines to spaces (single-line output). |
| `LinkToString()` | `Link?.LinkToString()` | Safe URL string from an Umbraco `Link` (handles null/empty). |
| `ToGuid()` | `Udi?.ToGuid()` | `GuidUdi` → `Guid` (`Guid.Empty` when null). |
| `ToJsonString()` | `IDictionary<string,string>.ToJsonString()` | Compact JSON serialisation. |

## 9.5 Sections (CSS placement)

`HtmlSectionBlockExtensions.SetSection(key, position)` lets a component register CSS/markup that the layout renders in the right place (deduplicated by `key`):

```razor
@using (Html.SetSection(Model.GetType().ToString(), HtmlSectionBlockExtensions.Position.BodyBottom))
{
    <link rel="stylesheet" href="~/css/@CurrentSite.GetItem().Root.Name/Components/MyComponent.css" />
}
```

For **JavaScript**, use the Script Queue instead of `<script>` tags — see [5. Script Queue](/5-Script-Queue/).

## 9.6 Colour & file utilities

- **`ColorHelper`** — `HexToRgb(hex)` (`#RGB`/`#RRGGBB` → `Color`), `RgbToHex(r,g,b)` / `RgbToHex(Color)`. Handy for CMS colour-picker values (e.g. the section wrapper in [7.4](/7-Content-Editing/#74-building-a-page-with-the-block-grid)).
- **`FileNameHelper.GetValidFileName(name)`** — sanitises a file name.
- **`MimeTypeMap`** — `GetMimeType(path)`, `TryGetMimeType(path, out mime)`, `GetExtension(mime)`.

## 9.7 Block preview aware components

Components can render a lighter output in the backoffice preview (CSS only, no JS):

```razor
@if (Context.Request.IsBlockPreviewRequest())
{
    <link rel="stylesheet" href="~/css/@CurrentSite.GetItem().Root.Name/Components/MyComponent.css" />
}
else
{
    // full render + Html.QueueScript(...) / QueueStandaloneScript(...)
}
```

See [10.3 Block Preview](/10-Backoffice-Tools/#103-block-preview).


## 9.8 CSS Architecture

uTPro uses a convention-based CSS structure in `wwwroot/css/{SiteName}/`:

```
css/uTPro/
├── variables.css        # ⭐ Design tokens (all colors, spacing, fonts)
├── critical.css         # Inlined in <head> for above-the-fold content
├── layout.css           # Reset + grid + typography
├── main.css             # Global components + responsive
├── navHeader.css        # Navigation + dropotron menu
├── wrapper.css          # Section wrapper (CMS-driven background/text colors)
├── icon.css             # Font Awesome (loaded async)
├── copyright.css        # Footer copyright
└── Components/          # ⭐ Per-component CSS
    ├── Article.css
    ├── BannerHeader.css
    ├── Breadcrumbs.css
    ├── ContactForm.css
    ├── CookieConsentBanner.css
    ├── Endorsements.css
    ├── Introduction.css
    └── IntroductionDetail.css
```

### Conventions

1. **Design tokens in `variables.css`** — Change one file to retheme the entire site. All colors use CSS custom properties.
2. **Critical CSS inlined** — `critical.css` is injected directly into `<head>` to eliminate render-blocking for above-the-fold content.
3. **Component CSS naming** — Each component has a matching CSS file: `uTPro__BannerHeader` → `Components/BannerHeader.css`. Register via `SetSection`:

```razor
@using (Html.SetSection(Model.GetType().ToString(), HtmlSectionBlockExtensions.Position.BodyBottom))
{
    <link rel="stylesheet" href="~/css/@CurrentSite.GetItem().Root.Name/Components/BannerHeader.css" />
}
```

4. **Async icon loading** — `icon.css` uses `media="print" onload` trick to avoid render-blocking.
5. **Multi-site support** — Each site gets its own folder name (`Root.Name`), enabling per-site theming.

### Adding a new component's CSS

1. Create `wwwroot/css/{SiteName}/Components/MyComponent.css`
2. In the component `.cshtml`, register it via `SetSection` (or inline in preview mode)
3. The CSS is only loaded when the component appears on a page (no unused CSS)

## 9.9 Block Preview View Resolution

Block Grid/List preview views are resolved using a multi-site convention:

**Pattern:** `~/Views/{SiteName}/blockgrid/Components/{ComponentName}.cshtml`

The system uses `CustomPathViews` to resolve views with a `{SiteName}__{ComponentName}` prefix convention. When a view is requested:

1. First checks for a site-specific view: `~/Views/{SiteName}/blockgrid/Components/{Component}.cshtml`
2. Falls back to the default: `~/Views/Partials/blockgrid/Components/{Component}.cshtml`

This allows per-site customization of component rendering without duplicating all views.

## 9.10 Category URL Extensions

For generating category-enriched URLs programmatically:

```razor
@* Get the category URL for a content node *@
@using uTPro.Project.Web.Configure

@* The CategoryUrlService is available via DI *@
@inject CategoryUrlService CategoryUrl
```

Category URLs are automatically generated for pages that have the `pageCategories` property set and the assigned category has `showInUrl` enabled. See [4.11 Category URL Routing](/4-Configurations/#411-category-url-routing).

## 9.11 Page Content Layout

`LayoutExtension` resolves the content layout preset for a page — `full` (default), `left-sidebar`, or `right-sidebar`:

```csharp
using uTPro.Extension;

var layout = Model.GetContentLayout(); // "full", "left-sidebar", or "right-sidebar"
var hasSidebar = layout.HasSidebar();  // true when left or right sidebar
```

**Resolution order:**
1. The page's own `layout` property
2. The nearest `globalFolderPages` container's `defaultLayout` property
3. System default: `full`

The datatype radio button list includes an "inherit" option, which is intentionally *not* a known layout — selecting it causes the resolver to fall through to the container default.

### In templates

```razor
@{
    var layout = Model.GetContentLayout();
}

<div class="content-layout content-layout--@layout">
    @if (layout == "left-sidebar")
    {
        <aside class="sidebar">@* sidebar blocks *@</aside>
    }
    <main>@* main content *@</main>
    @if (layout == "right-sidebar")
    {
        <aside class="sidebar">@* sidebar blocks *@</aside>
    }
</div>
```

## 9.12 Region Append (Inherited Top/Bottom Components)

`GetInheritedRegion` resolves a block-grid region (e.g. `topComponent`) as an ordered list of block grids to render, supporting both **override** and **append** modes:

```csharp
// Returns all block grids to render for the region (outermost ancestor first).
IReadOnlyList<BlockGridModel> regions = Model.GetInheritedRegion("topComponent", "topComponentAppend");
```

- If the owning node has the append flag **OFF** (default), only its own blocks are returned (override behaviour).
- If the append flag is **ON**, the system walks further up the tree and includes ancestor regions too, producing a stacked list (ancestor blocks first, then the current node's blocks).

This enables patterns like: site-wide header from Home + breadcrumbs from a section folder, without duplicating blocks.

## 9.13 Examine Search — Hidden Containers Excluded

Hidden container nodes (see [8.5](/8-Global-Settings/#85-hidden-container-urls)) are automatically excluded from the **ExternalIndex** (the index used for public site search). This means:

- Search results never return organisational folders
- The backoffice InternalIndex still includes them (so editors can find/manage them)
- Any doc-type alias in the hidden list (built-in + custom from `uTPro:HiddenUrls:DocumentTypeAliases`) is excluded

No additional configuration is needed — it works automatically based on the same `HiddenContainerAliases` used for URL suppression.
