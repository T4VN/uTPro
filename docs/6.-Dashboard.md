# 6. Dashboard & Header App

`uTPro.Feature.Dashboard` adds a branded **backoffice dashboard** and a **header app** to Umbraco. Both are backed by a single authenticated management-API controller, so nothing is exposed publicly and the GitHub "latest release" lookup happens server-side (cached) — the browser never calls GitHub directly.

## 6.1 What You Get

| Extension | Where | Purpose |
|-----------|-------|---------|
| **Header App** (`utpro-header-app`) | Top-right of the backoffice header | Popover card with the uTPro logo, installed version, an **Update** or **Check for Update** action, and a shortcut to the dashboard |
| **Dashboard** (`utpro-dashboard`) | Content section → **uTPro** tab | Welcome/overview page: version + update status, site statistics, current-user details, and recent activity / audit trail |

Both are registered in `App_Plugins/utpro-dashboard/umbraco-package.json`. The dashboard is shown in the Content section (`Umb.Condition.SectionAlias` = `Umb.Section.Content`).

## 6.2 Dashboard Layout

The dashboard uses a two-column layout (stacks on narrow screens):

- **Left (main)**
  - **Hero** — logo, product blurb, and either an "Update to vX" button or an "Up to date" tag + "Check for Update".
  - **Resources** — quick links (Documentation, Releases, Report an issue, Umbraco docs), built from the server-provided repo URLs.
  - **uTPro Apps** — auto-discovered sibling uTPro packages with links (see [6.3](#63-version--update-check)).
  - **SEO Audit · Score trend** — conditional card, only shown when `uTPro.Feature.SEOAudit` is installed and has ≥ 2 completed audit runs. Displays an SVG polyline chart of the last 10 health scores and a quick "Open →" link to the SEO Audit section. Detection is client-side (checks the extension registry for `uTPro.SeoAudit.Section`); the data is fetched from `/umbraco/management/api/v1/utpro/url-scan/runs?limit=10`. If the API is unreachable (package not installed or no permission), the card is simply hidden.
  - **Recent trail** — a single card with an **All / Yours** scope toggle (see [6.4](#64-recent-activity--audit-trail)).
  - **Recent activity** — two cards.
- **Right (sidebar)**
  - **Product Information** — product name, core (Umbraco) version, .NET runtime, installed version, latest release.
  - **Site** — published content, items in recycle bins, users/members totals and disabled counts.
  - **Installed uTPro Packages** — auto-detected list of uTPro feature packages with their versions.
  - **Your Details** — name, email, 2FA status, last login, last password change.

## 6.3 Version & Update Check

The header app and dashboard share version state via `config.js`:

- `GET version` returns `installed`, `latest`, `updateAvailable`, plus `website` / `releasesUrl`.
- The latest release tag is fetched from GitHub **server-side** and cached for 1 hour (avoids CORS, proxies, and rate limits).
- `GET version?refresh=true` (the "Check for Update" button) drops the server cache and re-checks immediately.
- Versions are normalized for display (`v17.0.4` → `17.0.4`).

## 6.4 Recent Activity & Audit Trail

The dashboard surfaces two kinds of history, each in a **"Your …"** (current user) and **"All …"** (everyone) card.

### Recent activity — from `umbracoLog`

Content-style actions (save, publish, create, move, delete, …). Each entry resolves the affected node's name and links to its editor:

| Entity type | Link target |
|-------------|-------------|
| `Document` | `/umbraco/section/content/workspace/document/edit/{key}` |
| `Media` | `/umbraco/section/media/workspace/media/edit/{key}` |
| `DictionaryItem` | `/umbraco/section/translation/workspace/dictionary/edit/{key}` |

> **Dictionary items** are not `umbracoNode` rows — their `NodeId` maps to `cmsDictionary.pk`. The controller joins `cmsDictionary` and resolves the name (the dictionary key, e.g. `uTPro.Form.ContactUs.Message`) and edit guid from there.

Each row shows the action, a status badge (Saved / Created / Published / …), and a meta line with the timestamp, the user (in the "All" card), and a friendly **entity type** label (`Document` → *Content*, `DictionaryItem` → *Dictionary*, …).

### Recent trail — from `umbracoAudit`

Cross-cutting events (sign-in, save, user management, …). This is a **single card** (the old separate "Your" / "All" cards are merged): a **grouped bar chart** compares everyone vs the current user per period, with a **scope toggle** and **time-range picker** above it and the newest detail rows below.

- **Chart**: a [Frappe Charts](https://frappe.io/charts) (MIT, vendored locally) grouped bar chart with **two datasets — "All" and "You"** — side by side per bucket, so you can compare your own activity against everyone's. Both scopes are fetched together per window (`recent-trail` + `my-trail`) and aligned by bucket. Colours use `--uui-color-selected` (All) and `--uui-color-warning` (You) so it follows light/dark mode; hover shows the exact count. A **summary line** above the chart shows both totals with matching colour dots (e.g. `● 22 All  ● 10 You  This week`).
- **Range picker** (`uui-select`, default *This month*): `week` (7 days, daily buckets), `month` (30 days, daily), `quarter` (90 days, weekly buckets), `year` (365 days, monthly buckets). Values must match the server's `TrailRanges`. Changing it refetches both scopes.

![Audit Trail Chart](/screenshots/dashboard-audit-trail.png)
- **Details** (collapsed by default): a **"Details" row with a caret** (`uui-symbol-expand`) sits below the chart. Clicking it reveals the scope tabs + the detail list; clicking again hides them.
  - **Scope tabs** (`uui-button-group`, default *All*): filter the list only (All = everyone, Yours = current user) — the chart always shows both, so switching needs no refetch. In *All* the rows also show the performing user.
  - **Detail list**: the newest `TrailListTake` (20) rows in the window for the active scope — event details, a meta line (timestamp + user) and the raw `eventType` as a tag.

> Audit-trail timestamps are stored in **UTC**; activity (`umbracoLog`) timestamps are stored in **local server time**. They are formatted with the browser locale, so the two rows can differ by your server's UTC offset.

## 6.5 Create Site

The dashboard includes a **Create Site** action that scaffolds a new site skeleton in the content tree with a single click. It creates:

1. **Global Root** (`globalFolderRoot`) — the top-level container
2. **Sites** (`globalFolderSites`) — the sites folder inside
3. **Navigation Link** (`globalFolderNavigationLinkForSite`) — menu folder

The action is available to **administrators** or users with unrestricted content-root access (no content start-node configured). Nodes are saved as **drafts** (not published), so you can build pages under the structure and publish when ready.

All cultures are set on culture-variant nodes automatically (based on installed languages), so the skeleton works immediately on multilingual sites.

## 6.6 CMS Login Screen Customization

`utpro-cms-screen` is a companion package (bundled with the Dashboard feature) that customizes the Umbraco **login/auth screen** with uTPro branding:

- **Brand colours** — the login page uses uTPro's orange accent (`#f6821f`) instead of Umbraco's default purple
- **Custom favicon** — the backoffice favicon is set to `logo.svg`
- **Custom greetings** — day-of-week greetings replace the defaults (e.g. "Happy funky Friday")
- **Curves hidden** — the decorative SVG curves on the login background are removed for a cleaner look

No configuration is required — the customization is applied automatically when the package is present. To revert to the default Umbraco login screen, remove or rename the `App_Plugins/utpro-cms-screen/` folder.

### File Locations

| File | Role |
|------|------|
| `App_Plugins/utpro-cms-screen/umbraco-package.json` | Registers the entry point and localization |
| `App_Plugins/utpro-cms-screen/index.js` | Injects the stylesheet and custom favicon |
| `App_Plugins/utpro-cms-screen/style.css` | CSS variable overrides for the login screen |
| `App_Plugins/utpro-cms-screen/lang/en-us.js` | Day-of-week greeting overrides |

## 6.7 Management API

All endpoints live under `/umbraco/management/api/v1/utpro/dashboard/` and require backoffice authentication.

| Endpoint | Returns |
|----------|---------|
| `GET version` (`?refresh=true`) | Installed + latest version and update status |
| `GET stats` | Site statistics (content, recycle bins, users, members, installed uTPro packages) |
| `GET current-user` | Current backoffice user details |
| `GET recent-activity` / `GET my-activity` | Newest `umbracoLog` entries (all users / current user) |
| `GET recent-trail` / `GET my-trail` (`?range=week\|month\|quarter\|year`) | `umbracoAudit` for the window (all users / current user) |
| `POST create-site` | Creates a new site skeleton (admin / root-access only) |

Activity endpoints return the newest 20 rows (`ActivityTake`). Trail endpoints take an optional `range` (default `month`) and return `{ range, from, to, total, series: [{ date, label, count }], items: [...] }` — `series` is the per-bucket chart data and `items` is the newest `TrailListTake` (20) detail rows in the window.

## 6.8 File Locations

| File | Role |
|------|------|
| `Controllers/uTProDashboardManagementController.cs` | All API endpoints; SQL for stats, activity (`umbracoLog`) and trail (`umbracoAudit`) |
| `App_Plugins/utpro-dashboard/umbraco-package.json` | Registers the header app + dashboard extensions |
| `App_Plugins/utpro-dashboard/config.js` | Shared config + authenticated `fetch*` helpers, version caching |
| `App_Plugins/utpro-dashboard/dashboard.element.js` | Dashboard element (layout, cards, node links, trail charts) |
| `App_Plugins/utpro-dashboard/header-app.element.js` | Header popover element |
| `App_Plugins/utpro-dashboard/vendor/frappe-charts.min.esm.js` | Vendored [Frappe Charts](https://frappe.io/charts) v1.6.2 (MIT) — renders the audit-trail bar charts. Loaded locally (no CDN); its CSS is inlined into the element's shadow styles since the library injects to `document.head`, which can't reach the shadow root |

> The `App_Plugins` files are static assets — after editing them, hard-refresh the backoffice to bypass the browser cache.
