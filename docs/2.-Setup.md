## 2.2 Setup Project
Setting up uTPro is simple. Once you have downloaded the source code, you can open the project solution file in Visual Studio. We recommend using Visual Studio 2022 (or later).

<img width="260" height="138" alt="Setup Visual Studio solution" src="/screenshots/uTPro/setup-visual-studio-solution.png" />

Then follow the minimum requirements of the Umbraco CMS project:

* Database: uTPro ships configured for **PostgreSQL** (default), and also supports **SQL Server** and **SQLite**. Change the ConnectionString in `appsettings.json` with key **umbracoDbDSN** => create an **empty database** on the chosen engine, then use its name/connection in **appsettings**. See [4.8 Database Provider](/4-Configurations/#48-database-provider-postgresql--sql-server--sqlite) for the connection string and provider name of each engine.

<img width="954" height="124" alt="Setup connection string" src="/screenshots/uTPro/setup-connection-string.png" />

* Target framework: .NET 10 (Changes depending on the Umbraco version in use — Umbraco 17 runs on .NET 10)

## 2.4 Troubleshooting

Common issues when setting up uTPro for the first time:

### Database connection fails

| Symptom | Cause | Fix |
|---------|-------|-----|
| `Login failed for user` | Wrong credentials or database doesn't exist | Create the database first (`CREATE DATABASE utpro;`), then verify username/password in connection string |
| `An error occurred using the connection` | Provider mismatch | Ensure `umbracoDbDSN_ProviderName` matches the engine: `Microsoft.Data.SqlClient` (SQL Server), `Npgsql` (PostgreSQL), `Microsoft.Data.Sqlite` (SQLite). See [4.8](/4-Configurations/#48-database-provider-postgresql--sql-server--sqlite) |
| `Could not find driver` / `Npgsql.NpgsqlException` | PostgreSQL server not running or wrong port | Verify PostgreSQL is running (`pg_isready`) and the port matches your connection string (default 5432) |
| `SQLite Error: unable to open database file` | Path permissions | Ensure the app has write access to the folder containing the `.db` file |

### Build / runtime errors

| Symptom | Cause | Fix |
|---------|-------|-----|
| `The project was restored using .NET 9` | Wrong SDK version | Install .NET 10 SDK (10.0.301+). Check with `dotnet --version`. `global.json` pins the expected SDK |
| `Could not find a part of the path 'umbraco/Data/TEMP'` | Missing temp folder permissions | Ensure the app pool identity has write access to `%TEMP%`. See [4.7](/4-Configurations/#47-multi-site-iis-hosting-load-balancing--moving-umbracodatatemp-out-of-the-project) |
| Runtime crash on first boot | Missing `appsettings.json` keys | Ensure `umbracoDbDSN` is set. On first boot with an empty DB, Umbraco runs the installer — follow the wizard |

### uSync import issues

| Symptom | Cause | Fix |
|---------|-------|-----|
| Import shows 0 changes | Already imported or wrong folder | Verify `uSync/` folder exists in the project root with `.config` files inside |
| Import errors on content | Missing document types | Import **Settings** first (or use "Everything" group which handles order automatically) |
| Languages missing after import | Languages not installed | Go to **Settings → Languages** and add them before importing content |

### First boot checklist

1. ✅ Database created (empty) and connection string set
2. ✅ .NET 10 SDK installed
3. ✅ `dotnet build` succeeds with no errors
4. ✅ `dotnet run` → navigate to `/umbraco` → complete the Umbraco install wizard
5. ✅ uSync import → refresh backoffice → content tree populated
6. ✅ Configure **Culture and Hostnames** on Home node (see [4.1](/4-Configurations/#41-configuration-remember-language---culture-and-hostnames))
